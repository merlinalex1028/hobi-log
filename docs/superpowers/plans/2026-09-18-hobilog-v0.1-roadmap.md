# HobiLog V0.1 实施计划总览（Roadmap）

> **For agentic workers:** 本文件是计划索引。每个子计划都是独立的实施文档，格式为 `docs/superpowers/plans/2026-09-18-hobilog-0N-<name>.md`，按其中任务逐条执行。

**Goal:** 按 `docs/` 设计稿把 HobiLog V0.1（手办预售订单 / 付款 / 出货 / 物流 / 收藏管理 Web）落地为可运行、可测试的 monorepo 产品。

**Architecture:** Vue3 Web 只做 UI 与交互，通过 REST + Bearer Supabase Access Token 访问 NestJS；NestJS 承担鉴权、业务规则、状态机与事务；Prisma 访问 Supabase PostgreSQL；文件走 Supabase Storage signed URL。核心边界：`Order ≠ Payment`、`Release ≠ Shipment`、`Product ≠ Order`。

**Tech Stack:** pnpm workspace / TypeScript 5.6 / NestJS 10 / Prisma 5.22 / Supabase (Auth + PostgreSQL + Storage) / Vue 3.5 + Vite 5 / Element Plus / TanStack Query / ECharts / FullCalendar / Jest + Supertest + Vitest。

---

## 为什么拆成多个子计划

设计稿覆盖 4 个可独立交付的子系统（工程底座、鉴权与基础资料、订单生命周期、统计与附件、前端），单文件计划会超过可维护长度，且每个子计划都能独立产出「可运行 + 有测试」的成果。按 `writing-plans` 的 scope check，拆分为 5 个子计划。

## 全局约束（所有子计划共同遵守）

复制自设计稿，逐字生效：

1. 业务对外访问路径只有一条：`Vue → NestJS REST API → Prisma → PostgreSQL`。业务页面禁止出现 `supabase.from('orders')` / `supabase.rpc(...)`，Web 端 Supabase SDK 仅用于 `supabase.auth.*` 与 Storage signed URL。
2. `userId` 永远来自经过验证的 Supabase Token，禁止信任 `body.userId` / `query.userId`；所有查询必须带 `where: { id, userId }`。
3. `OrderStatus` 仅 4 值：`ACTIVE | COMPLETED | CANCELLED | REFUNDED`。归档只用 `Order.archived: boolean`，不进入 `OrderStatus`。
4. 状态权威来源唯一：付款=`payments`，出货=`release_events`，物流=`shipments`，`DisplayStatus` 纯计算不落库。禁止 `orders.payment_status` / `orders.release_status` / `orders.shipping_status`。
5. `PaymentStatus` 落库 5 值：`PENDING | PAID | CANCELLED | REFUNDED | PARTIALLY_REFUNDED`；`OVERDUE` 动态派生（`status = PENDING 且 due_at < today`），不落库。
6. 退款单独建 `Payment(type = REFUND)`，金额用正数；禁止负数表示退款。
7. `Payment.amount = null` 合法（运费待定），不参与金额求和，但仍参与「存在待付款」判断；`due_at = null` 合法。
8. 订单总额与付款合计不强制一致（后补运费），只提示差额，不阻止。
9. 延期必须新增 `ReleaseEvent(type = DELAY)` 保留 `oldDate → newDate`，禁止覆盖原日期；累计延期按「初始预计 → 最新预计」的月份差计算。
10. 金额：数据库 `Decimal(14,2)`，API/JSON 统一返回 `number`；`BigInt`（`attachments.fileSize`）返回前转 string。
11. 统一错误体 `{ statusCode, code, message }`；Prisma `P2002 → 409`、`P2025 → 404`、`P2003 → 400`。分页返回 `{ items, total, page, pageSize }`。
12. 事务必须覆盖：创建订单、取消订单 + 取消未付节点、付款 + 补差价、退款、创建拆单物流、签收 + 刷新订单状态。
13. 多币种 V0.1 分开统计，禁止 `CNY + JPY + USD` 直接相加。
14. 工具链：Node >= 20.11、pnpm 9、TypeScript 5.6、`shared` 包编译为 CommonJS（Nest 与 Vite 均可消费）。
15. Prisma schema 与 migration 放在 `apps/server/prisma/`（与 `docs/04` 的 `pnpm --filter server exec prisma ...` 命令一致）；`docs/02 §32` 中的仓库级 `prisma/` 目录以本约束为准调整。

## 待用户提供的前置条件（P1 Task 6 会阻塞）

- `DATABASE_URL` / `DIRECT_URL`：Supabase PostgreSQL 连接串（应用连接 + 直连）。
- `SUPABASE_URL` / `SUPABASE_ANON_KEY` / `SUPABASE_SERVICE_ROLE_KEY`（P2 起需要，service role key 只存 Server）。
- 若暂时没有 Supabase 项目：可用本地 PostgreSQL 跑 migration（`DATABASE_URL` 指向 `postgresql://postgres:postgres@localhost:5432/hobilog`），Supabase Auth 相关任务延后到拿到凭据。

## 验收场景（跨计划，最终必须全绿）

来自 `docs/04 §19`、`docs/07 §96`、`docs/08 §25`：

```text
A 全款现货        FULL PAID + SHIPPED + DELIVERED → COMPLETED
B 全款预售        FULL PAID + EXPECTED_RELEASE → WAITING_RELEASE
C 定金尾款        DEPOSIT PAID + BALANCE PENDING → WAITING_PAYMENT
D 尾款逾期        BALANCE PENDING 且 due_at < today → PAYMENT_OVERDUE
E 延期            DELAY → WAITING_RELEASE（文案显示“延期”）
F 厂商出货        RELEASED 且无 Shipment → WAITING_SHIPMENT
G 运输中          Shipment IN_TRANSIT → IN_TRANSIT
H 物流异常        Shipment EXCEPTION → SHIPMENT_EXCEPTION
I 多包裹          1 DELIVERED + 1 IN_TRANSIT → IN_TRANSIT
J 全部签收        全部 DELIVERED 且无待付款 → COMPLETED
K 订单取消        Order CANCELLED → CANCELLED
L 退款结束        Order REFUNDED → REFUNDED
额外：金额待定补邮 / 拆单发货 / 用户 A 无法读取用户 B 数据 / Dashboard 统计
```
