# HobiLog V0.2 品牌与 UI 重构规划

> 目标：把 HobiLog 从“能管理订单的后台”升级为“收藏者每天愿意打开的个人藏品档案馆”。
>
> 本规划不沿用当前的极简后台视觉，改用更有收藏感、档案感和情绪价值的产品语言；业务能力仍保持现有的订单、付款、出货、物流、收藏与统计边界。

## 1. 产品定位

### 一句话定位

**HobiLog 是收藏者的个人藏品档案馆：记录每一件想要的、在路上的、已到家的东西。**

### 设计关键词

- 收藏柜：商品图片、系列、品牌和已拥有物品是主角。
- 档案卡：订单和付款不是冷冰冰的表格，而是可追踪的卡片记录。
- 时间线：预售、付款、出货、签收构成一条清晰的生命周期。
- 标签与印章：用轻量的状态标签制造收藏册般的识别感。
- 克制的玩味：有个性，但不能牺牲金额、日期、状态和操作的清晰度。

## 2. 视觉方向：柔和二次元收藏手帐

### 2.1 整体气质

采用“二次元收藏手帐 + 展示柜贴纸”的组合：暖黄色作为品牌主色，奶油色作为内容画布，蜜桃色和淡紫色承担状态与装饰信息。卡片使用圆润边角、柔和描边、纸张贴纸和小星芒等语言，但不加入角色、表情或过度幼态的装饰。

目标观感是：**像一本温柔、有收藏仪式感的二次元手帐，而不是一张通用 SaaS 控制台。**

### 2.2 色彩系统

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--cocoa-900` | `#4B3632` | 主文字、描边、主导航文字 |
| `--cocoa-700` | `#75554B` | 次级文字、深色按钮 |
| `--butter-500` | `#F6C85F` | 品牌主色、主行动、选中态 |
| `--honey-500` | `#E8A83E` | 主色深层、进度、强调边框 |
| `--vanilla-50` | `#FFF3D3` | 主内容背景、空白区域 |
| `--vanilla-100` | `#FFEAC0` | 卡片底色、分组背景 |
| `--peach-500` | `#FF9B83` | 待处理、提醒、收藏热度 |
| `--lavender-400` | `#A99AEF` | 物流中、辅助强调、图表系列 |
| `--mint-400` | `#91D5B8` | 已完成、已签收、健康状态 |
| `--line-soft` | `#E8CFA8` | 边框、分隔线、禁用底色 |
| `--text-primary` | `#3B2A28` | 内容区主文字 |
| `--text-secondary` | `#806A62` | 辅助说明、元信息 |

规则：暖黄色用于品牌和交互强调，不大面积用于正文背景上的小字；正文文字与背景保持至少 4.5:1 对比度；状态色不能只靠颜色区分，必须同时带文字或图形标识。

### 2.3 字体与排版

- 中文 UI：`Noto Sans SC`, `PingFang SC`, `Microsoft YaHei`, sans-serif；保持清晰，不使用过度装饰字体承载正文。
- 大标题与品牌短句：`Nunito`, `M PLUS Rounded 1c`, `Noto Sans SC`, sans-serif；使用圆润字形表达二次元手帐感。
- 数字与订单号：`Space Grotesk`, `Noto Sans SC`, sans-serif；金额、数量、日期使用等宽或数字 tabular-nums。
- 正文基准 14–16px，行高 1.55–1.7；标题使用明显的 1.25–1.35 层级。
- 任何页面的连续正文行长控制在约 65–75 个字符，避免宽屏上成为一条长灰带。

### 2.4 形状、边框与动效

- 主卡片圆角 22px，次级控件圆角 12–14px；允许少量胶囊标签，但主体容器保持柔和矩形。
- 纸张卡片使用 1.5px `--line-soft` 描边，搭配非常轻的暖色阴影，避免冷灰阴影。
- 状态标签可以使用“贴纸标签”造型：左侧小圆点 + 文案 + 星芒 / 印章图形。
- 空状态、加载态和商品图片占位优先使用圆角贴纸、纸胶带和柔和几何图案，不使用冷漠的灰色空框。
- 页面进入与卡片反馈只使用 transform/opacity，时长 160–260ms。
- 所有动画服从 `prefers-reduced-motion`；减少动效时仍保留状态变化和焦点反馈。
- 不使用 emoji 作为 UI 图标；图标统一使用 SVG 图标系统。

- 表格全部提供卡片视图；订单详情优先保证“金额、状态、下一步、时间线”可见。
- 筛选条件进入底部抽屉，支持清空、应用和已选条件回显。

## 4. 页面规划

### 4.1 今日 / Dashboard：今天的收藏柜

首屏不从 KPI 表格开始，而从“我现在最需要知道什么”开始：

1. **问候 + 收藏概览**：本月已付、待付、在途、已入库四个数字，配合小型趋势或变化文案。
2. **下一件会发生什么**：横向时间线，突出最近付款截止、预计出货和物流签收。
3. **最近到家**：大图卡片展示已签收商品，允许快速进入收藏详情。
4. **待处理清单**：付款、补充物流、确认签收、完善商品图片等行动项。
5. **轻量统计**：本月支出趋势、按平台金额、按类别件数；图表旁提供文本摘要。

Dashboard 的视觉锚点是商品图片和下一步行动，不是四个同样大小的数字卡。

### 4.2 订单：订单档案，而非普通数据表

- 默认提供“档案卡视图”和“紧凑表格视图”两种模式，记住用户上次选择。
- 档案卡显示：主商品图、店铺 / 平台、订单号、总金额、已付 / 待付、当前阶段、下一事件。
- 列表页顶部固定搜索与高频筛选；筛选结果以标签形式回显，支持一键清除。
- 订单详情采用左侧商品与付款主内容、右侧概览与操作的 split layout。
- 生命周期使用垂直时间线：下单 → 付款 → 预售 / 等待 → 出货 → 物流 → 签收；取消订单保留原始记录但明显标注。
- 付款节点在时间线中以可操作节点呈现；用户能直接看到“下一笔要付什么、什么时候付、还差多少”。

### 4.3 商品库：图片优先的收藏目录

- 默认使用 4/3/2 列响应式网格；商品图片作为第一视觉层，信息叠加在卡片底部。
- 卡片显示类别、IP、厂商、价格区间和在手 / 在途数量。
- 支持列表与网格切换；批量操作只在进入选择模式后出现，避免常驻噪音。
- 图片缺失时显示有品牌感的“档案占位卡”，不能只留一个空白灰框。

### 4.4 收藏库：展示柜模式

- 以“已入库商品”为主，默认展示大图、系列分组和拥有数量。
- 支持按 IP、类别、厂商、平台和入库时间过滤。
- 右上角展示收藏件数、系列数和本月新增；统计采用简短摘要，不抢商品展示。
- 详情中保留原始订单链接，让收藏记录和购买记录互相可追溯。

### 4.5 日历：事件优先

- 月视图用于总览，列表 / 时间线视图用于执行。
- 事件类型统一使用颜色 + 图形 + 文案：待付款、预计出货、已出货、物流签收。
- 点击事件打开抽屉，先给出下一步操作，再给出来源订单详情。
- 移动端默认列表视图，避免月历在小屏上变成不可读的色块矩阵。

### 4.6 统计：回答问题，而不是堆图表

统计页围绕四个问题组织：

- 钱花到哪里：按月、币种、平台和厂商的支出。
- 哪些收藏增长最快：类别、IP、厂商排行。
- 还有多少承诺未完成：待付款、未出货、在途金额与数量。
- 我的收藏节奏：入库趋势、系列完成度、月度新增。

推荐图表：金额趋势用折线 / 面积图，类别与平台用横向条形图，生命周期用阶段漏斗或堆叠条。每个图表必须提供可访问的图例、摘要文字和表格替代内容。

### 4.7 平台 / 店铺与设置

- 平台 / 店铺页采用“来源卡片”：logo、店铺名、订单数量、已付金额、最近订单。
- 设置页按“账户与安全、偏好、数据与附件、关于 HobiLog”分组，不做长表单。
- 低频危险操作放在页面底部的独立危险区，并要求明确确认。

## 5. 组件体系

### 一级组件

- `AppShell`：深色侧栏、顶栏、内容区域、移动端导航。
- `CollectorCard`：商品图、档案元信息、状态与快捷操作。
- `StatusStamp`：统一处理状态颜色、图形、文字与无障碍标签。
- `LifecycleTimeline`：订单、付款、出货、物流的统一生命周期组件。
- `NextActionCard`：把“下一步该做什么”放在视觉高优先级位置。
- `MoneySummary`：金额、币种、已付 / 待付，支持 tabular-nums。
- `FilterBar`：搜索、筛选、已选条件、清空与移动端抽屉。
- `ImagePlaceholder`：有品牌图案的图片缺失态、加载态和错误态。

### 交互底线

- 每个可点击图标按钮提供 `aria-label` 和可见 tooltip。
- 键盘焦点必须有清晰的 2px focus ring，不依赖颜色变化。
- 加载中的按钮禁用并保持原始宽度，避免内容跳动。
- 错误信息靠近出错控件，写明原因与可执行的修复动作。
- 删除、取消、归档等动作使用明确的确认文案，不使用模糊的“确定吗？”。

## 6. Logo 设计方向

### 6.1 概念：Hobi Soft Cabinet / 柔软收藏柜

logo 不直接画手办、角色或购物车，而是把“收藏柜、档案、贴纸印章”压缩成一个温柔的二次元符号：

1. 外层是圆润的暖黄色收藏柜轮廓，像一枚贴在手帐上的大号贴纸。
2. 内部用奶油色分隔结构暗示“档案路径”和时间线，不画细线。
3. 淡紫色展示格代表收藏物件的陈列感，但不出现具体角色或玩偶。
4. 蜜桃色星芒 / 小圆点作为收藏印章，成为远距离识别点。

建议的视觉组合：暖黄主形 + 奶油白留白 + 淡紫展示格 + 蜜桃色印章 + 可选薄荷绿完成态。图形使用圆润实心块面和柔和描边，不能依赖细线或复杂细节。

### 6.2 交付变体

- **Primary Mark**：透明底暖黄色图形标志，桌面侧栏、登录页、应用启动图使用。
- **Wordmark Lockup**：图形 + `HobiLog` 字标，登录页、空状态和关于页使用。
- **Small Mark**：仅保留暖黄色外轮廓、奶油色主块与一个蜜桃色识别点，favicon / 移动端使用。
- **Monochrome Mark**：纯可可棕和纯奶油白两个版本，用于打印、深色底和无障碍场景。

### 6.3 资产规格

```text
public/brand/
├── hobilog-mark.svg          # 主要网页使用，优先 SVG
├── hobilog-wordmark.svg      # 图形 + 字标
├── hobilog-mark-1024.png     # 透明底位图，设计稿与分享图使用
├── favicon.svg               # 16px / 32px 仍可辨识
├── favicon-32.png
├── apple-touch-icon.png      # 180×180
└── og-image.png              # 1200×630，带完整字标
```

虽然本次生成任务以位图为起点，但正式页面与 favicon 建议将最终图形重绘成 SVG；这样能保持锐利边缘、支持主题色切换和高 DPI 显示。位图版本保留透明通道，不在图片内嵌文字。

### 6.4 Logo 验收标准

- 16px favicon 仍能辨识“暖黄色外轮廓 + 主色块 + 蜜桃色识别点”。
- 32px 下没有需要猜测的细线、文字或微小装饰。
- 在 `--vanilla-50`、`--cocoa-900` 和纯白背景上都清楚。
- 不能与购物车、日历、普通文件夹或 generic SaaS 方块混淆。
- 图形有独立识别度，去掉 `HobiLog` 字标后仍然成立。

## 7. 实施顺序

### Phase 1：品牌基线

确定 logo、字标、颜色 tokens、字体、图标风格和空状态插画规则；补齐 favicon、manifest、登录页和侧栏品牌位。

### Phase 2：应用外壳

重做 `AppShell`、侧栏、顶栏、移动端底栏、全局搜索、快速新建和状态标签；业务数据与 API 不变。

### Phase 3：高频核心页

按 Dashboard → 订单列表 / 详情 → 收藏库 → 商品库顺序迁移，优先让“下一步动作、生命周期和商品图”成为主视觉。

### Phase 4：辅助页与一致性

迁移日历、统计、平台 / 店铺、设置；补齐错误态、空态、加载态、键盘焦点、响应式和 reduced-motion QA。

## 8. 完成判定

- 设计 tokens 只有一套来源，页面不再散落硬编码品牌色。
- 桌面端 1440px、平板 768px、移动端 390px 三档布局均可用。
- 核心业务任务：新建订单、标记付款、更新出货、查看物流、进入收藏库，在 3 次点击或 1 次表单提交内完成。
- 任何状态都同时具备颜色、文字和图形 / 位置提示。
- logo 在页面、favicon、深色和浅色底上通过验收，图片资源具备透明版本。
