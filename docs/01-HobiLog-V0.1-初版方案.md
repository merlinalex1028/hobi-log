# HobiLog V0.1 初版方案

> 面向手办、GK、模型、动漫周边等收藏品的个人订单管理 Web。

## 1. 产品定位

主要解决：

- 买了什么
- 在哪里买
- 总共多少钱
- 已经付了多少钱
- 后续还要付多少钱
- 什么时候补款
- 厂商什么时候出货
- 店铺什么时候发货
- 物流现在到哪
- 最终收藏了哪些商品

产品核心不是单纯记账，而是：

**订单生命周期管理 + 付款提醒 + 出货管理 + 收藏管理。**

---

## 2. 第一版目标

第一版优先解决三个问题：

1. 钱什么时候要付
2. 商品什么时候出货
3. 当前订单进行到什么阶段

暂时不做：

- 自动爬取商品数据
- 电商平台账号同步
- 自动物流查询
- OCR 自动识别
- 社区功能
- 二手交易
- 商品价格行情

---

## 3. 核心业务模型

```text
商品 Product
   │
   └── 订单项 OrderItem
            │
订单 Order ─┼── 付款节点 Payment
            │
            ├── 出货节点 ReleaseEvent
            │
            ├── 物流 Shipment
            │
            └── 订单事件 OrderEvent
```

## 6. 付款模型

付款不能写死为“定金 + 尾款”。

付款模式：

```text
FULL
全款

DEPOSIT_BALANCE
定金 + 尾款

INSTALLMENT
多阶段付款

CUSTOM
自定义付款
```

实际业务统一使用 `Payment` 节点。

### Payment 字段

- 付款类型
- 金额
- 状态
- 应付款日期
- 付款截止日期
- 实际付款日期
- 支付方式
- 支付平台
- 备注

付款类型：

- 全款
- 定金
- 尾款
- 阶段款
- 运费
- 补邮
- 税费
- 补差价
- 退款
- 其他

付款状态：

- 待付款
- 已付款
- 已逾期
- 已取消
- 已退款
- 部分退款

## 7. 三类典型订单

### 7.1 直接全款

```text
商品总额 ¥899

付款
✓ 全款 ¥899
  2026-09-18 已支付

未付款 ¥0
```

订单状态：

```text
已全款 / 等待出货
```

### 7.2 定金 + 尾款

```text
商品总额 ¥1299

✓ 定金 ¥300
○ 尾款 ¥999
  截止 2027-03-20
```

当前：

```text
已付定金
等待补款
```

### 7.3 多阶段 GK

```text
总价 ¥4280

✓ 一阶段款 ¥800
✓ 二阶段款 ¥1000
○ 尾款 ¥2280
○ 国内运费 待确定
```

## 8. 状态体系

不要使用单一订单状态。

### 付款状态

- 未付款
- 部分付款
- 已付款
- 已退款

### 商品 / 出货状态

- 预售中
- 制作中
- 等待出货
- 延期
- 厂商已出货
- 店铺已到货

### 物流状态

- 未发货
- 等待店铺发货
- 已发货
- 运输中
- 已签收
- 异常

最终展示可组合为：

- 已全款 · 等待出货
- 已付定金 · 等待补款
- 已补尾款 · 等待店铺发货
- 已付款 · 运输中
- 已签收 · 已完成

---

## 9. 出货记录

预计出货时间不能直接覆盖，应保留变化记录。

```text
初始预计出货
2027-01

第一次调整
2027-01 → 2027-03

第二次调整
2027-03 → 2027-05

实际厂商出货
2027-05-16
```

`ReleaseEvent` 可包含：

- 预计出货
- 延期
- 厂商出货
- 店铺到货
- 补款开始
- 实际发货

字段：

- 原日期
- 新日期
- 记录日期
- 来源
- 备注

后续可统计累计延期时长。

## 24. 核心设计原则

不要把业务写死成：

```text
depositAmount
balanceAmount
```

而是统一：

```text
Order
    ↓
Payment[]
```

示例：

```text
Order 总额 ¥4299

Payments
├─ 定金 ¥500
├─ 二阶段款 ¥800
├─ 尾款 ¥2999
└─ 补邮 ¥35
```

这样：

- 全款
- 定金尾款
- 三阶段 GK
- 补邮
- 补税
- 补差价
- 退款

都不需要改核心结构。
